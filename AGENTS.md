# Instrucciones de BUBA FRIENDS

## Publicación directa autorizada · preferencia del usuario, 31/10/2026

- Después de cada modificación solicitada en BUBA FRIENDS, ejecutar las comprobaciones disponibles y publicar directamente en el repositorio existente `Izangnz/buba-friends`, mediante GitHub Pages (`main` → `/docs`), sin solicitar otra autorización rutinaria para integrar, hacer push o publicar.
- Esta autorización incluye corregir los fallos que el usuario comunique y volver a publicar para que pueda probarlos. La revisión real en móvil/iPhone la hará el usuario después de publicar; su ausencia no justifica dejar una modificación solo en una candidata local.
- Antes de cada publicación: inspeccionar el estado local/remoto, conservar todo trabajo pendiente, guardar una referencia Git de recuperación de la versión pública actual y mantener el historial. Integrar los cambios revisados, regenerar `docs/` con el script existente y ejecutar las pruebas adecuadas.
- Verificar que el despliegue de Pages termina con éxito para el commit publicado y comprobar que los recursos públicos corresponden a las fuentes/publicables. Entregar siempre el enlace público con identificador de versión, el commit publicado y las limitaciones de comprobación, distinguiendo simulaciones de pruebas reales en móvil.
- Conservar perfiles, fotos, historias, colecciones, conversaciones y borradores. No reiniciar ni borrar almacenamiento del navegador; no incorporar imágenes personales, secretos o credenciales al repositorio, los paquetes ni las copias.
- Dejar algo sin publicar únicamente si el usuario lo pide expresamente para ese trabajo o existe un fallo conocido que impide publicar una versión utilizable. En ese caso explicar el impedimento y guardar el avance recuperable. Una dificultad de herramientas se debe intentar resolver antes de declarar bloqueo.
- Trabajar solo en BUBA FRIENDS; no modificar Hábitos ni otros proyectos. Se aplican además las instrucciones específicas de `codificacion/AGENTS.md`.
